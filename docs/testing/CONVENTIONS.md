# Binding conventions for the correction pass (13 Nov 2026)

These supersede anything in docs/testing/10 to 50 that disagrees. They were set after the independent review (docs/testing/REVIEW.md) and the cross-cutting document (50-risk-register-and-traceability.md). Docs/testing/00 will carry them as its canonical text.

C1 Test IDs. `T-<card>-<nnn>`, where <card> is the plan card ID with its dash kept (T-P0-05-014, T-P3-10-032). Exceptions: X-01 is `T-X01-nnn`; Android tests that belong to no single card are `T-AND-nnn`; gate tests are `T-GATE<n>-nnn` (T-GATE11-004); robot cards R-01 to R-09 are `T-RB<nn>-nnn` (T-RB02-031) so they cannot be confused with risk IDs; system-level tests are `T-SYS-nnn`. Three-digit zero-padded numbers. Ranges such as `T-P4-02-010..016` are forbidden: list every ID, or define one family ID `T-P4-02-F01` for a table-driven family and state its row count.
C2 Risk IDs. `R-<AREA>-<nn>`, areas FND, EYE, VOX, ID, SPA, MEM, RLZ, ROB, SYS. Unique across all documents: one canonical row in the owning card, and `See R-xx` cross-reference rows elsewhere (never a second differing copy). No suffix letters. The same risk has identical L, I and score everywhere. Score = L x I using INHERENT (before mitigation) values; add a Residual score column (L x I after mitigation). Recompute every score.
C3 Finding numbers. `<doc>-F<nn>` (10-F03, 20-F12, 30-F07, 40-F05, 45-F02, 50-F01). Convert old F-01, F1 and G-1 numbers and keep a one-line old-to-new table at the end of each document.
C4 Environment codes. ENV-0 pure function or unit; ENV-1 SimBody and loopback, no phone; ENV-2 ReplayBody on a recorded session; ENV-3 phone in the loop, scripted; ENV-4 human at a gate; ENV-5 robot on blocks; ENV-6 robot on the floor, supervised. Replace every local environment code. (Do not use E1 to E10 for environments: those are enforcement checks.)
C5 Statistics. Use Clopper-Pearson exact two-sided 95 percent intervals for every pass-count claim, and the rule of three (3/n, 95 percent one-sided) for zero-failure claims. Never quote an interval computed on the same set that was used to choose a threshold: choose thresholds on a calibration split and quote the bound on a disjoint held-out split, split by person-and-session, not by trial. Use session-level bootstrap only for dependent trials, and never present it when it collapses (zero errors). Call any gate with n below 30 a smoke test and say what it cannot show. Replace APCER with IAPMR where the attack-accepted rate is meant (ISO/IEC 30107-3 terms: IAPMR is the share of attacks accepted; APCER and BPCER are PAD-subsystem rates; check which is meant).
C6 Test layout. New tests go under `tests/<area>/` (unit, contract, golden, property, stateful, chaos, privacy, ml, compat, system). Fakes live in a package `tests/fakes/` with canonical names FakeModel (and its hostile subclass HostileModel), FakeAnthropic, FakeStt, FakeTts, FakeClock, LoopbackBody, FakeFs, FakeAdb, SynthMedia. The existing flat files in `tests/` stay where they are until touched; `tests/trace_map.toml` maps them to IDs.
C7 Limits. Every limit is a named constant in `brain/limits.py` and `Limits.kt`. The canonical list is the table in doc 00 Appendix A; documents must use those names. Where two documents proposed different names or values, Appendix A decides, and proposed values are marked provisional. Maximum utterance length is 15 s (the plan). Images: see Appendix A.
C8 Test-suite network policy. All tests run under a loopback-only egress policy (never the allowlist in config.toml). Anything that would contact a real vendor or the real model carries the marker `real_vendor`, is excluded from default pytest, and runs only by explicit command in a separate process with a spend cap. (The review found tests/conftest.py currently allows api.anthropic.com: record this as a defect to fix.)
C9 Physical test safety. Every procedure with a moving robot follows stages: S0 bench, motors unpowered; S1 on blocks, wheels off the ground, nobody touches wheels; S2 on the floor in an empty room with e-stop in hand; S3 floor with a person-presence test, only after S2 passes and with a held e-stop. Never hold a driven wheel. Never deep-discharge a lithium battery. Test procedures are reviewed against R-02 before use.
C10 Windows feasibility. Timing tests use a tolerance of at least 20 ms unless they use a high-resolution wait (a 1 ms asyncio sleep takes about 15.6 ms on Windows). Packages not installed (hypothesis, numpy, Pillow, bandit, pip-audit, mutmut) are marked 'to install'. mutmut on native Windows is unverified: name a fallback (for example cosmic-ray or a small scripted mutation runner). ROS 2 and Nav2 need Linux; WSL needs admin rights and is not available on this laptop, so Phase 6 integration testing assumes a separate Linux target.
C11 Deferral. The R-02 to R-09 robot test tables are marked Deferred until R-01 approves buying a robot; keep the designs but do not count them in the active totals. The 'first 100 tests' plan lives in doc 50.
C12 Oracles. No test oracle may say 'N', 'decide', 'stated rule' or similar. Replace each with a named constant (Appendix A; mark provisional values) or a decision ID `DEC-nn` that blocks the card until Jeff answers. Heading convention: use the BUILT convention (protocol/v0.md section 4.4 and Pose.heading_rad: counter-clockwise positive, so a left turn is positive) as the basis for every oracle, and record the plan's conflicting wording (P4-01 'positive clockwise', P4-05 'left negative') as DEC-HEADING with a recommended editorial fix to the plan.
